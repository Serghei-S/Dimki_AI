# Димки AI — 3D-лаборатория городской среды

Кнопка **«Отчёт»** открывает сравнение сценария, объяснения показателей и AI-помощника
через OpenRouter (бесплатный маршрут) или RiskRadar (оплаченная квота). Расчётная сводка и экспорт HTML, Markdown, JSON, CSV и
печать в PDF работают без ключа. Подключение AI через локальный `.env.local`, архитектура
и ограничения описаны в [docs/AI_REPORTS.md](docs/AI_REPORTS.md).

Теперь сайт по умолчанию открывает **реальный центр Обнинска**: 41 здание по контурам OpenStreetMap, улицы, отмеченные переходы и расчётная пешеходная сеть. Население и параметры остаются учебными. Прежний «Сосновый» сохранён в переключателе территорий. Происхождение, допущения и пересборка — в [docs/OBNINSK_CENTER.md](docs/OBNINSK_CENTER.md).

Редактор открывается первым. Добавление включает выбор места, предпросмотр и подтверждение одного объекта или набора. Школа и поликлиника требуют свободного эскизного участка; остановка — тротуара у улицы. Доступны также парковка, детская площадка и урна. «Среда» показывает расчётную доступность и сравнение до/после; режимы ходьбы свернуты внизу. Правила, ограничения и проверки — в [docs/CONTEXTUAL_EDITOR.md](docs/CONTEXTUAL_EDITOR.md).

Свободное размещение и перетаскивание объектов, важность, карта потребности, входы и вместимость парков, перенос и сравнение сценариев доступны в панели **«Редактор»** в обоих районах. Правила и ограничения — в [docs/FREE_EDITOR.md](docs/FREE_EDITOR.md).

Компактный режим размещения открывается кнопкой «Объект в любой точке». Отчёт показывает все категории доступности, зоны обслуживания и расчёт по домам с экспортом CSV/JSON. Проверенная цепочка расчётов, исправленные несогласованности и условия применения к реальным решениям — в [docs/PLACEMENT_AUDIT.md](docs/PLACEMENT_AUDIT.md).

Готовый синтетический набор данных для интерактивного конструктора городской среды. Он содержит геометрию, пешеходную сеть, население, объекты притяжения, проекты благоустройства и сценарии. Данные предназначены для редактора, расчётов доступности и будущего подбора проектов под бюджет.

Добавлено рабочее расчётное ядро TypeScript: применение сценариев, маршруты, расширяемые метрики, сравнение, точный подбор недоминируемых проектов и Web Worker. API и примеры интеграции — в [docs/ENGINE.md](docs/ENGINE.md).

```powershell
pnpm install --frozen-lockfile
pnpm verify
pnpm demo
pnpm bench
```

Рабочий локальный сайт включает 3D-макет, основную подсветку нагрузки рёбер (цвет и толщина по спросу всех жителей), отдельный включаемый слой фигур, слои доступности, выбор проектов, сравнение «До/После», сохранение сценариев и подбор улучшений под бюджет. Неподвижная карта перерисовывается по запросу.

Модель нагрузки, выполненная оптимизация, замеры и варианты Python/Node-бэкенда — в [docs/OPTIMIZATION.md](docs/OPTIMIZATION.md).

## Открыть карту

В этой папке дважды нажмите **`Запустить карту.cmd`** и откройте напечатанный адрес **http://127.0.0.1:5173/**. Окно запуска нужно оставить открытым. Для остановки нажмите Ctrl+C. Скрипт использует обычный Node.js или установленный локально комплект Codex.

Через терминал:

```powershell
pnpm dev
```

На другом компьютере нужны Node.js 22+ и pnpm, затем `pnpm install --frozen-lockfile`. Сайт работает через локальный HTTP-сервер; открытие `index.html` двойным щелчком не запускает модульный Worker.

```powershell
pnpm build       # проверка типов, сборка ядра и готового сайта в web-dist/
pnpm preview     # просмотр сборки на http://127.0.0.1:4173/
```

Управление: левая кнопка — перемещение, правая — поворот, колесо — масштаб. Нажмите на дом или найдите его через поиск: появятся маршрут, расстояние и ожидание на переходах. На узком экране панель района открывается кнопкой меню.

Архитектура карты, допущения анимации и направления расширения описаны в [docs/MAP.md](docs/MAP.md). Код интерфейса — `src/app/`, рендерера — `src/map/`, ядра — `src/core/`. Библиотечная сборка ядра по-прежнему доступна в `dist/engine.js` и `dist/engine.worker.js`; отдельно её собирает `pnpm build:core`.

**Район «Сосновый» полностью вымышленный.** Контуры, названия, жители, скорости, стоимости и ёмкости объектов сгенерированы. Приблизительная географическая привязка нужна только для отображения в картографической библиотеке; она не делает данные картой существующего района Обнинска.

## Файлы

- `data/district.json` — единственный источник истины для исходного района, проектов, профилей и сохранённых сценариев.
- `data/schema/district.schema.json` — строгий JSON Schema, draft 2020-12. Неизвестные поля запрещены.
- `data/schema/district.types.ts` — типы TypeScript, автоматически полученные из той же схемы для будущего интерфейса.
- `data/geojson/` — семь производных слоёв RFC 7946 для карты: дороги, кварталы, участки, здания, узлы, участки сети и объекты притяжения.
- `data/reports/baseline-metrics.json` — исходные показатели и результат по каждому жилому дому.
- `data/reports/scenario-comparison.json` — показатели шести сценариев, расходы и изменения относительно исходного состояния.
- `data/reports/project-effects.json` — эффект каждого проекта относительно его контекста зависимостей. Например, улучшение покрытия входа сравнивается с уже созданным сквером.
- `data/reports/validation.json` — результат проверки структуры, ссылок, геометрии, населения и проектов.
- `data/fixtures/regression-cases.json` — намеренно ошибочные или стрессовые случаи: изолированный дом, конфликт проектов, отсутствующая зависимость, превышение бюджета.
- `data/manifest.json` — SHA-256 исходного JSON, схемы, слоёв и контрольных примеров. Отчёты и изображения в манифест не включаются.
- `data/preview/district.svg` и `district.png` — обзорная карта для человека, не источник данных.
- `docs/DATA_MODEL.md` — описание полей, алгоритмов, операций и тонких мест интеграции.

**GeoJSON нельзя редактировать независимо от исходного JSON.** Он пересоздаётся генератором. В слое точек объектов парк отображается у первого входа; площадь парка берётся из слоя участков, а маршруты рассчитываются до всех его входов.

## Пересоздание и проверка

Генератор, валидатор, эталонные расчёты и тесты используют только стандартную библиотеку Python 3.10+. Генерация детерминирована: версия данных `1.0.0`, seed `20402026`. Нет сетевых запросов и внешних источников данных. Приведённые ниже команды предполагают доступный `python`; в Codex используется найденный через workspace dependencies комплектный Python.

```powershell
python tools/build_dataset.py
python -m unittest discover -s tests -v
python tools/render_preview.py
```

Первая команда пересоздаёт JSON, схему, GeoJSON, контрольные примеры и расчётные отчёты и выполняет полную проверку. Она не обновляет документацию и растровый предпросмотр. Для нового варианта без перезаписи исходных данных:

```powershell
python tools/build_dataset.py --output path/to/another-dataset
python tools/validate_dataset.py path/to/another-dataset/district.json
python tools/render_preview.py --data path/to/another-dataset/district.json --output path/to/map.svg
```

SVG автономный, его можно открыть в браузере. PNG — производное изображение; для него нужен любой SVG-рендерер. В подготовленном комплекте он уже есть.

Дополнительная независимая проверка схемы возможна стандартным пакетом `jsonschema` версии 4: `Draft202012Validator.check_schema(schema)` и `Draft202012Validator(schema).validate(data)`. Основной валидатор проекта проверяет используемый в схеме набор правил без установки зависимостей.

## Порядок подключения к приложению

1. Загрузить `district.json`, проверить `metadata.schemaVersion`, создать индексы по `id`.
2. Нарисовать геометрию; для MapLibre использовать производные слои или преобразовать локальные координаты по описанной формуле.
3. Хранить исходный район неизменяемым. Текущий сценарий — список проектов и эксплуатационных изменений.
4. Проверить зависимости, взаимоисключения и капитальный бюджет. Применить операции к копии района в указанном порядке.
5. Собрать активный граф для профиля, рассчитать время до каждого типа объектов и сравнить с исходным состоянием.
6. После редактирования обновлять и граф, и картографические слои. Статические GeoJSON описывают только исходное состояние.
7. Использовать готовое ядро TypeScript из `src/core/`; его результаты сверяются с контрольными отчётами, включая недостижимость, направления рёбер и профиль без ступеней.

## Границы модели

Это основа для объяснимой оценки пешеходной доступности при заданных допущениях. Она не прогнозирует пробки, загруженность автобусов, выбросы, температуру, безопасность движения, юридическую допустимость строительства и реальную стоимость работ. Вместимость и население ближайших домов показаны отдельно от пешей доступности; занятость мест, часы работы и перераспределение посетителей не ограничивают маршрутизацию. Есть каталог проектов и свободное размещение входов объектов с разрезанием рёбер, а также внутренние пути парков. Произвольное рисование новых улиц потребует расширения правил валидации и версии контракта.

Метрики разных профилей и категорий объектов нельзя складывать как уникальных людей. Все три профиля оценивают одних и тех же жителей при разных предположениях о передвижении.
