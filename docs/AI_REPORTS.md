# Отчёт и AI-помощник

Кнопка **«Отчёт»** в шапке открывает снимок завершённого расчёта текущего сценария.
Во время предпросмотра размещения и пересчёта создание отчёта недоступно.
В окне оставлена только панель AI с вопросом, выводом и числовыми основаниями.
Нажатие на показатель под ответом открывает его формулу и источник.

Основные показатели находятся во вкладке «Среда»: индекс близости и жители с трудным
доступом. Для каждого показаны «До» (исходный район) и «После» (текущий сценарий),
а под значениями — смысл и правило расчёта. Категории объектов свёрнуты в детали;
повторные таблицы, сводки сети, расходов и благоустройства убраны.

## Выбор сервиса

Сервис выбирается только на сервере через `AI_PROVIDER` в `.env.local`.
Ключи независимы: RiskRadar не получает ключ OpenRouter и наоборот. URL API фиксированы
в серверной конфигурации; браузер не может подменить адрес или выбрать другую модель.

### RiskRadar — оплаченная квота

Для активированного API-ключа (не промокода) задайте:

```dotenv
AI_PROVIDER=riskradar
RISKRADAR_API_KEY=ваш_ключ
RISKRADAR_MODEL=gemini-2.5-flash
```

Адрес: `https://riskradarai.ru/v1/chat/completions`. Bearer-авторизация и формат
Chat Completions. `gemini-2.5-flash` — имя модели из каталога и модель по умолчанию
этого шлюза; приложение не может независимо подтвердить фактическую модель за шлюзом.
Это сторонний сервис с оплаченной квотой, а не бесплатный API Google.
Один запрос ограничен 3500 выходными токенами. Автоматического перехода на другую
модель здесь нет. Ошибка недостаточного баланса показана отдельно. Параметры
маршрутизации и ограничения цены OpenRouter этому сервису не отправляются.

Сервис и модель ответа доступны в свёрнутом блоке «Как подготовлен ответ» и в экспорте.
Расчётные данные передаются выбранному сервису только по нажатию «Получить вывод».

### OpenRouter — бесплатный маршрут

Установите `AI_PROVIDER=openrouter` и выполните следующие шаги.

1. Создайте собственный ключ на https://openrouter.ai/settings/keys.
2. Скопируйте `.env.example` в `.env.local` в корне проекта.
3. Заполните `OPENROUTER_API_KEY=ваш_ключ`, без префикса `VITE_`.
4. Запустите `pnpm dev`, откройте отчёт и нажмите «Получить вывод». Ключ перечитывается
   сервером при запросе. После изменения настроек переоткройте отчёт или нажмите
   «Повторить подключение», если показана ошибка. Переменные окружения процесса имеют приоритет.

`.env.local` исключён из Git. Ключ не передаётся браузеру, не включается в клиентскую
сборку и не выводится в ответах API. В этой версии нет интерфейса для ввода ключа в браузере.

На Windows сервер также использует доверенные корневые сертификаты системы,
сохраняя стандартные сертификаты Node.js и проверку HTTPS. Это поддерживается в
Node.js 22.19+ и 24.5+ через `tls.setDefaultCACertificates`:
https://nodejs.org/api/tls.html#tlssetdefaultcacertificatescerts.
Если старая версия Node сообщает об ошибке цепочки сертификатов, обновите Node.

Основная модель — `nvidia/nemotron-3.5-super-vl:free`, выбранная для аналитического текста
и структурированного отчёта. Официальная карточка на 17 октября 2026 года подтверждает
нулевую стоимость входных/выходных токенов, контекст 1M и поддержку JSON Schema через
`response_format`. Это инженерный выбор, не собственный сравнительный бенчмарк.
Наличие модели не гарантирует свободную ёмкость провайдеров. Ранее использовавшаяся
Qwen3.8 27B исключена из списка запросов при переключении модели пользователем.

При недоступности основной модели OpenRouter пробует `openrouter/free`.
Все варианты бесплатные. `provider.max_price` устанавливает
нулевой предел для входных, выходных токенов и платы за запрос, а `require_parameters`
требует поддержки параметров структурированного ответа. Платного fallback нет.
Общий лимит ответа — 6000 токенов, бюджет рассуждения — 1536; скрытые рассуждения в UI
не возвращаются. Фактическая модель записывается в отчёт. Доступность, квоты и задержки
определяет провайдер. Локальный сервер не гарантирует доступность внешнего сервиса.

Документация провайдера:

- https://openrouter.ai/docs/guides/routing/routers/free-router
- https://openrouter.ai/docs/api_reference/authentication
- https://openrouter.ai/docs/api_reference/limits
- https://openrouter.ai/nvidia/nemotron-3.5-super-vl:free
- https://openrouter.ai/docs/guides/routing/model-fallbacks
- https://openrouter.ai/docs/guides/routing/provider-selection

## Что делает AI

В интерфейсе одно поле необязательного вопроса и кнопка «Получить вывод». Без вопроса
помощник оценивает пользу решения для жителей, недостатки и следующий шаг. Ответ
содержит короткие выводы, действия и существенные неизвестные; числовые основания
показываются рядом и открывают пояснения по нажатию. Переключатели режимов и статус
настроенного ключа убраны; ошибки подключения и повторная попытка сохранены.
Состав передаваемых данных описан в свёрнутом блоке «Как подготовлен ответ»: сводные
показатели, названия изменений, допущения и вопрос. Геометрия и строки по отдельным
домам исключены. Не вводите личные сведения в названия объектов и вопрос.

Сервер заново рассчитывает сценарий на локальном наборе данных и проверяет SHA256.
Он не принимает готовые численные показатели, URL провайдера или имя модели от клиента.
Ответ привязан к точному сценарию и профилю. Числа в карточках оснований берутся из ядра.

AI возвращает ограниченный JSON: выводы, рекомендации, ограничения. Каждый вывод и
рекомендация должны ссылаться на существующие идентификаторы фактов. Числовые литералы
в повествовании отклоняются: значения показывает приложение по ссылкам. Это проверка
формата и оснований, **не доказательство правильности интерпретации**. Качественные
ошибки модели возможны; пояснение об AI доступно в блоке «Как подготовлен ответ». AI не изменяет сценарий, не запускает
код, не обращается к инструментам и не обещает эффект непроверенных изменений.

JSON Schema, передаваемая провайдеру, содержит те же ограничения длины, количества
элементов и числовых литералов, что и серверная проверка. Тест проверяет эту схему
независимым JSON Schema-валидатором до имитации ответа модели.

Отмена и закрытие окна прерывают запрос. Есть таймаут, ограничение размера запроса/ответа,
не более двух одновременных запросов и десяти запросов в минуту на локальный процесс.
Ошибки ключа, квоты, недоступности и некорректного ответа показаны отдельно от расчёта.
Текст провайдера не вставляется как HTML, экспорты экранируют содержимое.

## Экспорт (программный модуль)

Кнопки экспорта убраны из окна «Отчёт»; функции `src/reports/export.ts` сохранены.

- **HTML** — автономный оформленный отчёт без внешних ресурсов и исполняемых скриптов.
- **PDF / Печать** — открывает системную печать подготовленного HTML; выберите сохранение
  в PDF. Это печать отчёта, а не экспорт скриншота карты.
- **Markdown** — текст, таблица показателей, AI-комментарии и допущения.
- **JSON** — полный снимок, исходный сценарий, параметры, факты, строки домов и AI-ответ.
- **CSV** — строки «дом × категория», исходные секунды, население и флаги охвата;
  без AI-повествования. UTF-8 с BOM, разделитель `;`, защита от формул в строковых ячейках.

## Запуск и границы

Для простого сервера по IP доступен `pnpm start` после `pnpm build`: отдельный Node HTTP-сервер
отдаёт `web-dist/` и обслуживает AI API. Точный внешний адрес задаётся в `PUBLIC_ORIGIN`, например
`http://203.0.113.10:4173`; ключ читается из `.env.local`. Инструкция: [QUICK_SERVER.md](QUICK_SERVER.md).
Для этого режима не нужны Vite preview, домен, Nginx или сертификат. Проверка Host/Origin сохранена;
публичный origin разрешается только явно. Аутентификация пользователей в этом простом запуске не добавляется.

Для локальной разработки API также реализован middleware Node/Vite для `pnpm dev` и `pnpm preview` (после `pnpm build`).
Оба сервера привязаны к loopback. Проверяются Host и Origin; CORS для внешних сайтов не
открыт. Сервер использует `dist/engine.js` и `dist/report.js`, которые собирает штатный
build. Копирования одного `web-dist/` на статический хостинг недостаточно для AI.
Для публичного размещения нужен отдельный сервер с аутентификацией и лимитами пользователей.

Расчётная сводка и экспорт не требуют ключа или внешнего API. Если API недоступен,
они остаются доступны; не выдаём шаблонную сводку за ответ языковой модели.

Трава — декоративные диски в одном instanced mesh, в слое деревьев. Радиус ограничен
точными расстояниями до границ квартала, дорог, зданий и пешеходных рёбер с учётом ширины.
Она не меняет граф, население, площадь общественных парков или показатели обеспеченности.

## Проверки

Автоматические тесты проверяют сверку отчёта с ядром, общие достижимые группы,
изоляцию данных, HTML/CSV-инъекции, проверку сценариев сервером, бесплатный маршрут,
неизвестные ссылки AI, ошибки провайдера, отсутствие ключа, Origin/Host, размер запроса,
таймаут, отмену и локальные квоты. Ответ провайдера в тестах подменяется явно.
Геометрические тесты проверяют безопасные радиусы травы на реальном наборе Обнинска.

17 октября 2026 года проверено реальное подключение RiskRadar: авторизация и
каталог моделей вернули HTTP 200. Полный запрос через локальный `/api/assistant/analyze`
заново рассчитал исходный Обнинск и вернул HTTP 200 примерно за четыре секунды:
модель `gemini-2.5-flash`, три вывода и две рекомендации. JSON и ссылки на факты
прошли штатную серверную проверку. Это проверка подключения и формата, не сравнительная
оценка качества модели и не гарантия будущей доступности сервиса.

Ранее запросы к OpenRouter из среды разработки получили HTTP 403:
`Access denied by security policy`, включая чтение каталога. Inference после запрета
не выполнялся; авторизация старого ключа OpenRouter не подтверждена.

`/api/assistant/status` сообщает загрузку ключа и конфигурацию, без внешнего запроса:
сам по себе этот статус не подтверждает авторизацию. Ключи хранятся в игнорируемом
`.env.local`; проверены на отсутствие в отслеживаемых файлах Git и клиентской сборке.
Живой браузер и PDF-диалог не проверены из-за ранее отклонённого доступа к localhost.
